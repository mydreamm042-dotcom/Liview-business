# MILESTONES

버전(마일스톤)별로 뭐가 들어가는지 기록한다. `ROADMAP_V2.md`의 **Phase**가 "개발 순서"라면,
여기 **버전**은 "`main`에 실제로 릴리스된 단위"다 — 여러 Phase가 한 버전으로 묶여 병합되기도
하고, 한 Phase가 여러 버전에 걸쳐 나뉘어 들어가기도 한다.

버전 번호는 시맨틱 버저닝(`MAJOR.MINOR.PATCH`)을 따르고 `package.json`의 `version`과 항상
일치시킨다. `main`에 의미 있는 PR이 머지될 때마다 이 표와 `package.json`을 함께 갱신한다.

버전 경계(어디까지가 몇 버전인지)와 각 버전의 포함 범위는 사용자가 정한다.

| 버전 | 상태 | 포함 범위 |
|------|------|-----------|
| v0.0.1 | 릴리스됨 (main) | 시작점 |
| v0.1.0 | 계획 (사용자 확정, 2026-08-11 범위 수정) | 가설 A+C 동시 검증 — 지도 게이팅 없이 `main`의 전체 범위 그대로(지도 "입장하기"→방화면 + 지도/Discovery 포함, QR 스캔은 더 이상 필수 아님 — ADR-0006) |

### 지도 화면 처리 — 2026-08-10 최종 결정: 막지 않는다

애초엔 v0.1.0에서 지도를 코드는 두고 접근만 막는 "게이팅" 방식을 검토했다(가설 A를 단독으로
보기 위해). 근데 지도가 이미 다 완성돼 `main`에 있는데, 그걸 굳이 숨기는 로직(리다이렉트/
플래그)을 새로 만드는 게 이 시점엔 불필요한 엔지니어링이라고 판단해 **막지 않고 처음부터
전체 범위로 연다.** 대신 가설 A 지표(방 화면 리액션)와 가설 C 지표(지도/매장상세 조회)는
따로 관찰한다 — 상세: ADR-0005.

이 결정으로 v0.1.0/v0.2.0 구분(지도 유무로 나뉘던 것)이 없어졌다. 다음 버전 번호는 실제
파일럿 이후 새로운 의미 있는 단위가 생길 때 정한다.

## 원칙

- 버전 경계는 "사용자가 실제로 써볼 수 있는 단위"를 기준으로 잡는다 — Phase 하나가 끝났다고
  자동으로 버전이 올라가지는 않는다(작은 Phase 여러 개가 한 버전으로 묶일 수 있음)
- `main`에 아직 머지되지 않은 버전은 "코드 완료, main 미반영" 또는 "미착수"로 상태를 명확히
  구분한다 — "완료"는 오직 `main`에 실제로 들어간 것만
- 이 표는 `ROADMAP_V2.md`(Phase 상세 스코프)를 대체하지 않는다 — 이 표는 "언제 뭐가 나갔는지"
  요약이고, 각 항목의 세부 규칙/미확정 사항은 `ROADMAP_V2.md`/`BUSINESS_RULES.md`를 따라간다
- 버전 경계/포함 범위는 Claude가 임의로 정하지 않는다 — 항상 사용자와 논의 후 확정

# MySTAR/Liview B2B 로드맵 v2

## 이 문서의 위치
기존 `B2B_PIVOT_DESIGN.md`(섹션 7)와 `IMPLEMENTATION_CHECKLIST.md`가 Phase 순서를 정의했지만, 새 아이디어(지도 기반 홈 화면)가 그 순서에 영향을 주므로 **이 문서가 Phase 순서에 대해 최신 기준**이다. 세부 태스크 체크리스트는 기존 `IMPLEMENTATION_CHECKLIST.md`를 계속 참고하되, 몇 번째로 하느냐는 이 문서를 따른다.

---

## 이번에 반영된 새 아이디어

> "Liview 기본 화면 = 지도. 사용자가 위치 기반으로 가게를 찾아갈 수 있게. 하단 UI: 입장하기 / 실시간 핫한 가게 찾기 / 방만들기. '실시간 핫한 가게 찾기'는 방의 실시간 HOT 지수·만족도·채팅을 볼 수 있고 카테고리/정렬 가능. 단, 방 코드는 제공하지 않는다 (원격 참여 악용 방지)."

이건 새 도메인이 아니라, **이미 설계해둔 Discovery 도메인의 역할이 커진 것**이다. 원래 설계(v1 addendum)에서 Discovery는 "BUSINESS 방 나가기 후 다음 코스 추천"이라는 부가 기능이었는데, 이번 아이디어로 **앱의 기본 진입점(홈 화면)**이라는 훨씬 무거운 역할을 겸하게 됐다. 그래서 로드맵에서 우선순위가 크게 앞당겨진다.

새로 추가된 핵심 규칙(`BUSINESS_RULES.md` §2.6에 반영 완료): **Discovery 화면(홈 지도 포함)은 방 코드/QR을 절대 노출하지 않는다.** 참여는 반드시 실제 방문 + QR 스캔으로만 가능하다.

## 재정렬된 Phase 순서

| Phase | 내용 | 상태 |
|-------|------|------|
| **1** | Foundation — venues 테이블, room_type, closed 상태 | ✅ 완료 (main 병합) |
| **2** | Room Configuration — 매장 브랜딩, 운영자 설정 화면 | ✅ 완료 (main 병합) |
| **3 (신규 승격)** | **Liview 홈 — 지도 진입점 + 실시간 탐색 (Discovery + Public Transparency MVP)** | 다음 작업 |
| 4 (기존 3에서 밀림) | 운영자 대시보드 | 대기 |
| 5 (기존 4 + Staff 추가안 통합) | 이벤트 타임라인 + 직원 교대/친절도 평가 | 대기 |
| 6 (기존 5 + Review 추가안 통합) | 리뷰 유도 + 검증 리뷰(venue_reviews) | 대기 |
| 7 (기존 6) | Polish & Integration | 대기 |

**바뀐 것은 순서뿐, 내용은 그대로다.** 기존 Phase 3(운영자 대시보드)이 사라진 게 아니라 Phase 4로 밀렸을 뿐이고, Phase 1/2는 이미 끝났으니 전혀 건드리지 않는다.

## Phase 3 상세 — Liview 홈 (지도 + 실시간 탐색)

### 왜 이걸 다음으로 당겼나
- 사용자가 "앱의 기본 화면"이라고 못박았다 → 다른 어떤 기능보다 먼저 마주치는 화면이라 우선순위가 가장 높다.
- 필요한 하부 데이터(Venue의 위치/카테고리, HOT 지수, 만족도)는 **이미 Phase 1에서 준비되어 있다** (`venues.latitude/longitude/category`, `get_reaction_summary`). 추가 스키마가 거의 필요 없어 지금 바로 시작 가능하다.
- Public Transparency(공개 채팅)는 원래 별도 Phase였지만, "채팅을 실시간으로 볼 수 있음"이 이번 요구사항에 포함되어 있어 최소 기능만 여기로 당겨왔다 (opt-in 토글 + 읽기 전용 API만. 운영자 설정 UI 고도화는 이후 Phase에서 다듬어도 됨).

### 스코프
1. **`get_live_hot_venues()` 함수 실제 마이그레이션 반영** — 지금까지는 `docs/b2b-pivot/B2B_MIGRATION_V2.sql`에 설계만 되어 있고 `supabase/migrations/`에는 아직 적용 안 됨
2. **`GET /api/discover/venues`** — 위치 기반 실시간 HOT 매장 목록 (카테고리 필터, 거리순/HOT순 정렬)
3. **홈 화면 교체** — 기존 `src/app/page.tsx`(방 만들기/참여하기 버튼만 있는 화면)를 지도 기반 화면으로 교체
   - 하단 3버튼: **입장하기**(기존 "방 참여하기"와 동일 기능, 이름만 변경) / **실시간 핫한 가게 찾기**(신규) / **방 만들기**(기존)
4. **매장 카드/상세 화면** — 실시간 HOT 지수, 평균 만족도, 카테고리 표시. `public_chat_enabled`인 매장만 채팅 프리뷰 노출. **방 코드/QR은 절대 표시하지 않음**
5. **공개 채팅 최소 기능** — `venues.public_chat_enabled` 토글(운영자) + 읽기 전용 공개 채팅 API (이미 Phase 1 스키마에 `public_chat_enabled` 컬럼 있음)

### 미확정 — 실제 구현 전 결정 필요
- **지도 SDK**: 카카오맵 / 네이버지도 / 구글맵 중 선택 (보류 중, 다음 대화에서 결정)
- Discovery 화면을 PERSONAL 참여자에게도 홈 화면으로 그대로 보여줄지 확인 필요 — "Liview 기본 화면"이라고 하신 걸 "전체 공개 홈"으로 해석했으나, 확정 필요

### 영향받지 않는 것
- 기존 PERSONAL 방의 QR/코드 입장 흐름은 전혀 바뀌지 않는다 (버튼 이름과 화면 배치만 바뀜)
- Phase 1/2에서 만든 API/DB는 수정 없이 그대로 재사용

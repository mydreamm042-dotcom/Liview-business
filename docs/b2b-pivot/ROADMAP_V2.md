# MySTAR/Liview B2B 로드맵 v2

## 이 문서의 위치
기존 `B2B_PIVOT_DESIGN.md`(섹션 7)와 `IMPLEMENTATION_CHECKLIST.md`가 Phase 순서를 정의했지만, 새 아이디어(지도 기반 홈 화면, 좌석 배치, 손님 케어)가 그 순서에 영향을 주므로 **이 문서가 Phase 순서에 대해 최신 기준**이다. 세부 태스크 체크리스트는 기존 `IMPLEMENTATION_CHECKLIST.md`를 계속 참고하되, 몇 번째로 하느냐는 이 문서를 따른다.

이 문서는 계속 갱신된다 (v2 안에서 개정). 새 아이디어가 들어올 때마다 새 파일을 또 만들지 않고, 이 문서 하나를 최신 상태로 유지한다 (`CHANGE_INTAKE_PROCESS.md` 원칙).

## 지금까지 반영된 새 아이디어

### ① 지도 기반 홈 화면 + 실시간 핫플레이스 탐색
> "Liview 기본 화면 = 지도. 하단 UI: 입장하기 / 실시간 핫한 가게 찾기 / 방만들기. 방 코드는 제공하지 않는다 (원격 참여 악용 방지)."

새 도메인이 아니라, 이미 설계해둔 **Discovery 도메인**의 역할이 커진 것 (부가 기능 → 앱의 기본 진입점). 핵심 신규 규칙: **Discovery 화면은 방 코드/QR을 절대 노출하지 않는다** (`BUSINESS_RULES.md` §2.6).

### ② 좌석 배치도(자리배치) + 좌석별 실시간 HOT 표시 + 운영자 좌석 이동
> "가게 입장 시 자리배치도로 이동해 좌석 선택. 좌석마다 HOT 탭 여부 표시. 운영자가 손님 좌석을 드래그(모바일 롱프레스 2초)로 옮기면 참여자 화면에도 반영됨 — 손님이 잘못 앉았을 때 사장님이 고치는 용도. 좌석마다 착석 경과시간 타이머도 표시."

새로운 **Seating 도메인**을 도입 (`BUSINESS_RULES.md` §2.7). 좌석 선택, 운영자의 좌석 강제 이동(+실시간 참여자 화면 반영), 착석 경과시간 타이머까지 확정됐다.

### ③ 손님 케어 (경고 메시지 / 쿠폰 지급)
> "자리배치도에서 손님을 우클릭(모바일=터치)하면 경고 메시지(자유 입력)/쿠폰(매장 등록 카탈로그 중 선택) 지급 가능. 앞으로 기능이 더 늘어날 가능성 높음."

새로운 **Guest Care 도메인**을 도입 (`BUSINESS_RULES.md` §2.8). Seating과 트리거 화면은 같지만(자리배치도), "위치"가 아니라 "그 손님에게 무엇을 하는가"를 다루는 별개 도메인이다 — 액션이 계속 늘어날 걸 감안해 확장형으로 설계. **주의**: 기존 Reaction 도메인의 `warning`(참여자 간 익명 자제 시그널)과 이름이 겹치므로, 신규 기능은 "운영자 경고 메시지(Operator Alert)"로 명확히 구분한다.

## 재정렬된 Phase 순서

| Phase | 내용 | 상태 |
|-------|------|------|
| **1** | Foundation — venues 테이블, room_type, closed 상태 | ✅ 완료 (main 병합) |
| **2** | Room Configuration — 매장 브랜딩, 운영자 설정 화면 | ✅ 완료 (main 병합) |
| **3** | Liview 홈 — 지도 진입점 + 실시간 탐색 (Discovery + Public Transparency MVP) | 다음 작업 |
| **4** | 좌석 배치 & 좌석 선택 + 운영자 좌석 이동 + 손님 케어 MVP (Seating + Guest Care) | 스펙 대부분 확정 |
| 5 (기존 3에서 밀림) | 운영자 대시보드 | 대기 |
| 6 (기존 4 + Staff 추가안) | 이벤트 타임라인 + 직원 교대/친절도 평가 | 대기 |
| 7 (기존 5 + Review 추가안) | 리뷰 유도 + 검증 리뷰(venue_reviews) | 대기 |
| 8 (기존 6) | Polish & Integration | 대기 |

**바뀐 것은 순서뿐, 내용은 그대로다.** 이미 끝난 Phase 1/2는 건드리지 않는다.

## Phase 3 상세 — Liview 홈 (지도 + 실시간 탐색)

### 스코프
1. `get_live_hot_venues()` 함수 실제 마이그레이션 반영 (현재 `B2B_MIGRATION_V2.sql`엔 설계만 있고 `supabase/migrations/`엔 미적용)
2. `GET /api/discover/venues` — 위치 기반 실시간 HOT 매장 목록 (카테고리 필터, 정렬)
3. 홈 화면 교체 — `src/app/page.tsx`를 지도 기반으로. 하단 3버튼: 입장하기 / 실시간 핫한 가게 찾기 / 방 만들기
4. 매장 카드/상세 화면 — 실시간 HOT·만족도, opt-in 매장만 채팅 프리뷰. **방 코드/QR 절대 미표시**
5. 공개 채팅 최소 기능 — `venues.public_chat_enabled` 토글 + 읽기 전용 API

### 미확정
- 지도 SDK (카카오맵/네이버지도/구글맵) — 보류 중
- Discovery 홈을 PERSONAL 참여자에게도 그대로 보여줄지

## Phase 4 상세 — 좌석 배치 + 운영자 좌석 이동 + 손님 케어

### 왜 Phase 3 바로 다음인가
- 참여자 흐름상 "지도에서 매장 발견 → 실제 방문 → QR 입장 → **좌석 선택**"으로 자연스럽게 이어지는 다음 단계다.
- Seating과 Guest Care는 같은 화면(자리배치도)에서 동작하므로 한 Phase로 묶어 구현하는 게 효율적이다.

### 스코프 — Seating (확정)
1. `venue_seat_layouts`(가칭) — 매장 좌석 배치 데이터, 운영자가 구성 (Phase 2 브랜딩 편집기 패턴 재사용)
2. `participants.seat_id` + `seat_assigned_at` — 참여자가 선택/배정된 좌석과 배정 시각
3. 참여자용 자리배치도 화면 — 좌석 선택 UI, 좌석별 실시간 HOT 표시(파생), 착석 경과시간 타이머(파생)
4. **운영자 좌석 이동** — 자리배치도에서 드래그(모바일: 롱프레스 2초)로 특정 참여자의 좌석을 변경 → 해당 참여자 화면에 실시간 반영 (Room 도메인의 기존 realtime 구독 패턴 재사용 가능)

### 스코프 — Guest Care (확정된 부분)
5. 자리배치도에서 손님 우클릭(모바일: 터치) → 액션 메뉴
6. **운영자 경고 메시지** — 자유 텍스트 입력 후 특정 손님에게 발송 (`operator_alerts` 신설, `reactions.warning`과는 별개 테이블/개념)
7. **쿠폰 지급** — 매장 쿠폰 카탈로그(`venue_coupons`) 중 하나를 선택해 특정 손님에게 지급 (`coupon_grants` 신설)
8. 액션 로그는 감사 이력으로 보존 (삭제 안 함)

### 미확정 — 스펙 대기
- 좌석 선택이 필수인지 스킵 가능한지
- 좌석 이동 시 착석 타이머가 리셋되는지 (현재는 "리셋"으로 해석해뒀음 — 확인 필요)
- 경고 메시지가 참여자 화면에 어떻게 노출되는지 (팝업/배너/알림)
- 쿠폰 등록 화면/데이터 구조 (운영자가 쿠폰을 앱에 등록하는 플로우)
- 쿠폰 수령 확인/사용 방법
- Guest Care에 추가될 예정이라고 언급된 "그 외 기능들" — 구체화되는 대로 계속 반영

### 영향받지 않는 것
- PERSONAL 방에는 좌석/손님케어 개념 자체가 없다 (Venue가 없으므로)
- 기존 QR 입장 흐름은 그대로, 입장 "다음" 단계로 좌석 선택이 추가될 뿐
- Reaction 도메인의 기존 `warning`(자제 시그널) 로직은 전혀 건드리지 않는다

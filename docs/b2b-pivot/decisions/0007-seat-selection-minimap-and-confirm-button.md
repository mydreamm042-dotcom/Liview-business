# ADR-0007: 좌석 선택 화면 — 미니맵 + "선택완료" 버튼 도입 (2단계 선택 흐름)

- **상태**: Accepted (코드 반영 완료)
- **날짜**: 2026-08-12
- **관련 문서**: `BUSINESS_RULES.md` §2.8, ADR-0001(부분 수정)

## 맥락

사용자가 CGV 좌석 예매 화면(전체 배치 미니맵 + 뷰포트 표시 + 하단 "선택완료" 버튼)을
참고 사례로 제시하며, 참여자용 좌석 선택 화면(`/room/[code]/seat`)에 같은 패턴을 적용하고
싶다고 요청했다. 새 도메인이 아니라 Phase 9에서 이미 완료·병합된 Seating 도메인(§2.8) 화면의
UI 확장이다.

ADR-0001은 "좌석을 선택하는 순간 방 입장이 즉시 확정"되는 1단계 흐름을 확정했었다.
"선택완료" 버튼을 추가하려면 이 부분을 바꿔야 한다 — 좌석 탭이 더 이상 즉시 확정이 아니라
가선택(하이라이트)이 되고, 최종 확정은 버튼을 눌러야 일어난다.

## 결정

1. **좌석 탭 = 가선택, "선택완료" 버튼 = 확정 (ADR-0001 수정)**: 좌석을 탭하면 하이라이트만
   되고 방 입장은 아직 확정되지 않는다. 화면 하단에 새로 추가되는 "선택완료" 버튼을 눌러야
   비로소 "방 입장"이 완료 처리되고 방 화면으로 전환된다. 확정 전에는 다른 좌석을 다시 탭해
   가선택을 바꿀 수 있다(재선택 가능).
2. **미니맵 항상 표시**: 좌석 선택 화면에 전체 좌석 배치를 축소한 미니맵을 좌석 배치 규모와
   무관하게 항상 보여준다.
3. **뷰포트 표시**: 미니맵 위에 현재 화면에 보이는 스크롤/확대 범위를 사각형으로 함께
   표시한다.
4. **확대/이동은 버튼이 아니라 제스처 (2026-08-12 갱신)**: 처음엔 미니맵 옆에 `+`/`−` 버튼을
   뒀으나, 사용자가 CGV 등 실제 지도/좌석 앱과 같은 조작감(두 손가락 핀치로 확대·축소, 손가락
   또는 마우스 드래그로 이동)을 요청해 버튼을 없애고 제스처로 교체했다.

## 버린 대안

- **탭 = 즉시 확정 유지, 버튼은 보조 확인용**: ADR-0001의 1단계 흐름을 그대로 두고 버튼은
  단순 확인 팝업만 띄우는 방식도 검토했으나, CGV 참고 사례의 의도(확정 전 재선택 허용)와
  맞지 않아 기각 — 사용자가 2단계 흐름을 직접 선택
- **미니맵 조건부 표시(뷰가 확대/스크롤된 상태일 때만)**: 좌석 수가 적어 미니맵이 필요 없는
  매장까지 고려한 절충안이었으나, 사용자가 "항상 표시"를 선택 — 매장마다 조건을 분기하는
  복잡도보다 단순함을 우선

## 데이터 영향

없음 — 기존 `venue_seats`/`venue_layout_items`(좌표계 §2.8 "좌석 배치 자유 구성"과 동일,
캔버스 대비 0~100% 좌표) 데이터를 그대로 재사용하는 순수 UI 확장이다. 새 테이블/컬럼 없음.

  보유)를 썼다 — 이 화면은 로딩 중엔 `<LoadingScreen/>`만 그리다가 나중에야 실제 캔버스가
  마운트되는데, 빈 deps 이펙트는 그 첫 마운트(로딩 화면) 시점에 한 번만 돌고 끝나 실제
  캔버스가 나타나는 순간을 놓치는 버그가 있었다(Playwright로 실제 클릭/줌을 확인하다 발견)
- tsc/vitest(179)/build 통과. Playwright(사전 설치된 Chromium)로 가선택→재선택→확정 전체
  흐름과 확대/스크롤에 따른 미니맵 뷰포트 갱신을 실제 브라우저에서 확인

**2026-08-12 추가 갱신 — 확대/이동을 버튼에서 제스처로 전환.** `+`/`−` 버튼을 없애고
Pointer Events로 두 손가락 핀치 확대/축소 + 한 손가락(또는 마우스) 드래그 이동을 직접
구현했다(트랙패드 Ctrl+휠도 핀치와 동일하게 처리). Playwright로 실제 제스처를 재현하며 버그
3건을 발견·수정했다:
- `setPointerCapture` 실패 시 예외가 핸들러 전체를 중단시키던 문제
- **`setPointerCapture`를 모든 탭에 걸어두면, 스펙상 그 이후 발생하는 `click`까지 캡처한
  요소로 강제 리타겟된다** — 정작 눌린 좌석 버튼은 이벤트 경로에서 빠져 `onClick`이 영영 안
  불리는 치명적 문제였다. 캔버스가 화면 대부분을 차지해 캡처 없이도 실사용에 지장이 없다고
  보고 캡처 자체를 제거했다
- 핀치 제스처는 손을 떼도 브라우저가 `click`을 발생시키지 않아, "드래그 직후 click 억제"
  플래그가 다음 진짜 탭까지 영원히 막던 문제 — 포인터가 모두 떨어지면 `setTimeout(0)`으로
  안전망 리셋을 추가해 해결

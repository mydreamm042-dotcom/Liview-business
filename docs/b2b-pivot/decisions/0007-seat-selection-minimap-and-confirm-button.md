# ADR-0007: 좌석 선택 화면 — 미니맵 + "선택완료" 버튼 도입 (2단계 선택 흐름)

- **상태**: Accepted (코드 반영 완료, 2026-08-12)
- **날짜**: 2026-08-12
- **관련 문서**: `BUSINESS_RULES.md` §2.8, ADR-0001(부분 수정)

## 맥락

사용자가 CGV 좌석 예매 화면(전체 배치 미니맵 + 뷰포트 표시 + 하단 "선택완료" 버튼)을
참고 사례로 제시하며, 참여자용 좌석 선택 화면(`/room/[code]/seat`)에 같은 패턴을 적용하고
싶다고 요청했다. 새 도메인이 아니라 Phase 9에서 이미 완료·병합된 Seating 도메인(§2.8) 화면의
UI 확장이다.

ADR-0001은 "좌석을 선택하는 순간 방 입장이 즉시 확정"되는 1단계 흐름을 확정했었다.
"선택완료" 버튼을 추가하려면 이 부분을 바꿔야 한다 — 좌석 탭이 더 이상 즉시 확정이 아니라
가선택(하이라이트)이 되고, 최종 확정은 버튼을 눌러야 일어난다.

## 결정

1. **좌석 탭 = 가선택, "선택완료" 버튼 = 확정 (ADR-0001 수정)**: 좌석을 탭하면 하이라이트만
   되고 방 입장은 아직 확정되지 않는다. 화면 하단에 새로 추가되는 "선택완료" 버튼을 눌러야
   비로소 "방 입장"이 완료 처리되고 방 화면으로 전환된다. 확정 전에는 다른 좌석을 다시 탭해
   가선택을 바꿀 수 있다(재선택 가능).
2. **미니맵 항상 표시**: 좌석 선택 화면에 전체 좌석 배치를 축소한 미니맵을 좌석 배치 규모와
   무관하게 항상 보여준다.
3. **뷰포트 표시**: 미니맵 위에 현재 화면에 보이는 스크롤/확대 범위를 사각형으로 함께
   표시한다.

## 버린 대안

- **탭 = 즉시 확정 유지, 버튼은 보조 확인용**: ADR-0001의 1단계 흐름을 그대로 두고 버튼은
  단순 확인 팝업만 띄우는 방식도 검토했으나, CGV 참고 사례의 의도(확정 전 재선택 허용)와
  맞지 않아 기각 — 사용자가 2단계 흐름을 직접 선택
- **미니맵 조건부 표시(뷰가 확대/스크롤된 상태일 때만)**: 좌석 수가 적어 미니맵이 필요 없는
  매장까지 고려한 절충안이었으나, 사용자가 "항상 표시"를 선택 — 매장마다 조건을 분기하는
  복잡도보다 단순함을 우선

## 데이터 영향

없음 — 기존 `venue_seats`/`venue_layout_items`(좌표계 §2.8 "좌석 배치 자유 구성"과 동일,
캔버스 대비 0~100% 좌표) 데이터를 그대로 재사용하는 순수 UI 확장이다. 새 테이블/컬럼 없음.

## 후속 작업

**2026-08-12 코드 반영 완료** (ADR-0008과 한 번에 구현 — 같은 화면군의 같은 UI라 나눠서
작업할 이유가 없었다). 구현 내용:
- `src/app/room/[code]/seat/page.tsx` — 좌석 탭이 `pendingSeatId` 상태만 바꾸도록 변경(기존
  즉시 API 호출 제거), 하단 고정 "선택완료" 버튼 추가(가선택 없으면 비활성화). 버튼을 눌러야
  `PATCH /api/participants/seat` 호출 후 방 화면으로 이동한다
- 미니맵/뷰포트는 `SeatMap` 컴포넌트에 내장했다(ADR-0008 "다른 화면으로의 동일 적용") —
  `src/components/CanvasMiniMap.tsx` + `src/hooks/useZoomPan.ts`
- 구현 중 확인된 것: 미니맵은 캔버스 우상단에 떠 있어서 그 자리에 실제 좌석이 배치된 매장에선
  좌석을 가린다. 반투명 배경 + `pointerEvents:'none'`으로 처리해 **가려져도 비쳐 보이고 탭도
  그대로 통과**하게 했다(미니맵 자체는 조작 대상이 아니므로 클릭을 받을 이유가 없다)

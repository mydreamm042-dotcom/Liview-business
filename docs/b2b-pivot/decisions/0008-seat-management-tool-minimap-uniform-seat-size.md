# ADR-0008: 좌석 관리 툴 — 미니맵/확대축소/드래그 전 화면 적용 + 장식 요소 종류 정리 + 좌석 고정 크기

- **상태**: Accepted (문서만, 코드 미착수)
- **날짜**: 2026-08-12
- **관련 문서**: `BUSINESS_RULES.md` §2.8, ADR-0007(같은 화면군의 UI 확장을 이어감)

## 맥락

ADR-0007에서 참여자 좌석 선택 화면에 미니맵+뷰포트+선택완료 버튼을 확정했다. 사용자가
이어서: 사장님(운영자)의 매장 규모가 천차만별이고 2층·3층 등 다층 매장도 있어, 운영자 설정의
좌석 배치 편집 화면에도 같은 확대/축소·미니맵이 필요하다고 요청했다. 코드 확인 결과 이
화면(`/operator/settings/[id]/seats`)은 `SeatMap` 컴포넌트를 재사용하지 않는 독자적인
편집기라, 참여자 좌석 선택 화면(`/room/[code]/seat`)·방 화면(`/room/[code]`)과는 구현이
분리되어 있다 — 후자 둘만 `SeatMap` 컴포넌트를 공유한다.

논의 중 추가로 확정된 것: (1) 장식 요소 `table` 종류가 `box`와 기능이 겹쳐 폐지, 대신 `line`
신설, (2) 장식 요소 크기 제한(최소 4%, 최대 제한 포함) 전면 폐지, (3) 좌석은 개별 크기 조절이
아니라 전부 동일한 고정 크기로 통일(기존 `table` 장식 요소들의 평균 크기 근거), (4) 좌석 복제
기능 신설.

## 결정

1. **운영자 설정 좌석 편집 화면**(편의상 "좌석 관리 툴"이라 부르되 이건 정식 명칭이 아니라
   비공식 호칭 — 사용자가 명시적으로 "이름은 편한 대로 부를 것"이라고 확인)에 전체 배치
   미니맵 + 현재 뷰포트 표시 + 확대/축소/드래그(터치 핀치·마우스 스크롤/드래그 전용, 별도
   버튼 없음)를 자체 구현으로 추가한다.
2. **`SeatMap` 컴포넌트를 공유하는 다른 화면**(참여자 좌석 선택 화면, 방 화면의 자리배치도 —
   손님 읽기전용 뷰 + 운영자 좌석 이동 뷰)에도 동일한 미니맵+뷰포트+확대/축소/드래그를
   똑같이 적용한다. 매장 상세 바텀시트의 좌석 탭(§2.7)은 `SeatMap`을 쓰지 않는 단순 점유
   숫자 카운트라 대상이 아니다.
3. **장식 요소(`venue_layout_items`) 종류 변경**: `table` 폐지(→ `box`로 대체 가능), `line`
   신설. 최종 종류: `box` / `door` / `text` / `line`.
4. **장식 요소 크기 제한 전면 폐지**: 기존 `MIN_SIZE_PCT`(4%) 최소 크기 제한과, 존재했던 최대
   크기 제한을 모두 없앤다 — 매장이 넓거나 다층인 경우 확대해서 아주 작게 배치하고 선/텍스트로
   자유롭게 안내할 수 있어야 하기 때문.
5. **좌석 고정 크기**: 좌석(`venue_seats`)은 개별 크기 조절 기능을 갖지 않고, 전부 동일한
   고정 크기로 렌더링된다. 이 값은 DB에 저장하는 게 아니라 렌더링 상수(현재
   `SeatMap.tsx`의 38px 원형)를 교체하는 방식이며, 폐지되는 `table` 장식 요소들의 평균
   크기(26×16%)를 근거로 구현 시점에 구체 값을 정한다. 저장값이 아니므로 이미 배치된 좌석도
   코드 배포와 동시에 새 크기로 즉시 반영된다("실시간 반영"의 실체 — 별도 마이그레이션 불필요).
6. **좌석 복제(복사) 기능 신설**: 운영자가 좌석 관리 툴에서 기존 좌석을 복사해 빠르게 추가할
   수 있다. 트리거 UI와 라벨 자동 증가 여부는 미확정 — 구현 시점에 정한다.

## 버린 대안

- **좌석에도 개별 `width`/`height` 컬럼 추가해 크기 조절 가능하게** — 검토됐으나, 사용자가
  "동일한 크기로 확정해 버리기"를 명시적으로 선택 — 좌석 크기는 통일하고 배치의 자유도는
  장식 요소(제한 없는 box/door/text/line)로 확보하는 쪽으로 역할을 나눔
- **운영자 설정 화면도 `SeatMap` 컴포넌트를 공유하도록 리팩토링** — 사용자가 "여긴 이미
  관리 에디터/툴이 있으니까" 제외를 명시 — 지금은 두 구현을 통합하지 않고 각자 미니맵/줌/팬을
  자체 구현하는 것으로 확정(리팩토링 여부는 코드 작업 시점에 별도 판단)

## 데이터 영향

- `venue_layout_items.kind` CHECK 제약을 `('table','box','door','text')`에서
  `('box','door','text','line')`으로 변경하는 마이그레이션 필요 (기존 `table` 행 처리 방식은
  미확정 — 그대로 두고 렌더링만 무시할지, `box`로 일괄 변환할지 코드 작업 시 결정)
- `venue_seats`에는 스키마 변경 없음 (크기가 저장값이 아니라 렌더링 상수이므로)

## 후속 작업

**코드 미착수.** 구현 시 필요한 것:
- 운영자 설정 좌석 편집 화면: 미니맵/뷰포트/줌·팬 제스처 핸들링 자체 구현
- `SeatMap` 컴포넌트: 동일한 미니맵/뷰포트/줌·팬 추가 (좌석 선택 화면·방 화면 공용이라 여기
  한 번만 구현하면 두 화면에 자동 반영)
- `LayoutItemShape`/에디터의 `kind` 목록에서 `table` 제거, `line` 렌더링(두 점 또는
  위치+각도+길이 등 좌표 모델은 미확정) 추가
- `MIN_SIZE_PCT` 및 존재하는 최대 크기 제한 코드 제거
- 좌석 고정 크기 값 산출(기존 `table` 평균 크기 실측) 후 `SeatMap.tsx` 상수 교체, `VARIABLES.md` 갱신
- 좌석 복제 UI/API 신설
- `venue_layout_items.kind` CHECK 제약 마이그레이션 + 기존 `table` 행 처리 방식 결정

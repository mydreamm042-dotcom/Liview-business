# ADR-0008: 좌석 관리 툴 — 미니맵/확대축소/드래그 전 화면 적용 + 장식 요소 종류 정리 + 좌석 고정 크기

- **상태**: Accepted (코드 반영 완료, 2026-08-12)
- **날짜**: 2026-08-12
- **관련 문서**: `BUSINESS_RULES.md` §2.8, ADR-0007(같은 화면군의 UI 확장을 이어감)

## 맥락

ADR-0007에서 참여자 좌석 선택 화면에 미니맵+뷰포트+선택완료 버튼을 확정했다. 사용자가
이어서: 사장님(운영자)의 매장 규모가 천차만별이고 2층·3층 등 다층 매장도 있어, 운영자 설정의
좌석 배치 편집 화면에도 같은 확대/축소·미니맵이 필요하다고 요청했다. 코드 확인 결과 이
화면(`/operator/settings/[id]/seats`)은 `SeatMap` 컴포넌트를 재사용하지 않는 독자적인
편집기라, 참여자 좌석 선택 화면(`/room/[code]/seat`)·방 화면(`/room/[code]`)과는 구현이
분리되어 있다 — 후자 둘만 `SeatMap` 컴포넌트를 공유한다.

논의 중 추가로 확정된 것: (1) 장식 요소 `table` 종류가 `box`와 기능이 겹쳐 폐지, 대신 `line`
신설, (2) 장식 요소 크기 제한(최소 4%, 최대 제한 포함) 전면 폐지, (3) 좌석은 개별 크기 조절이
아니라 전부 동일한 고정 크기로 통일(기존 `table` 장식 요소들의 평균 크기 근거), (4) 좌석 복제
기능 신설.

## 결정

1. **운영자 설정 좌석 편집 화면**(편의상 "좌석 관리 툴"이라 부르되 이건 정식 명칭이 아니라
   비공식 호칭 — 사용자가 명시적으로 "이름은 편한 대로 부를 것"이라고 확인)에 전체 배치
   미니맵 + 현재 뷰포트 표시 + 확대/축소/드래그(터치 핀치·마우스 스크롤/드래그 전용, 별도
   버튼 없음)를 자체 구현으로 추가한다.
2. **좌석 배치도(캔버스)를 보여주는 다른 모든 화면**에도 동일한 미니맵+뷰포트+확대/축소/드래그를
   똑같이 적용한다 — 참여자 좌석 선택 화면, 방 화면의 자리배치도(손님 읽기전용 뷰 + 운영자
   좌석 이동 뷰), **매장 상세 바텀시트의 좌석 탭(§2.7)**. **(2026-08-12 범위 정정)**: 애초엔
   바텀시트 좌석 탭이 `SeatMap`을 안 쓰는 단순 점유 숫자 카운트(`VenueDetailSheet.tsx`
   구현)라 제외했으나, 사용자가 "좌석배치도인데 왜 빼냐"고 지적 — 원래 §2.7 규칙 문구도
   "어떤 좌석이 비어있는지"였지 집계 숫자가 아니었다. 이 탭도 실제 `SeatMap` 캔버스로
   렌더링하도록 승격하고(비참여자 읽기전용, 클릭 불가), 미니맵 적용 대상에 포함한다.
3. **장식 요소(`venue_layout_items`) 종류 변경**: `table` 폐지(→ `box`로 대체 가능), `line`
   신설. 최종 종류: `box` / `door` / `text` / `line`.
4. **장식 요소 크기 제한 전면 폐지**: 기존 `MIN_SIZE_PCT`(4%) 최소 크기 제한과, 존재했던 최대
   크기 제한을 모두 없앤다 — 매장이 넓거나 다층인 경우 확대해서 아주 작게 배치하고 선/텍스트로
   자유롭게 안내할 수 있어야 하기 때문.
5. **좌석 고정 크기**: 좌석(`venue_seats`)은 개별 크기 조절 기능을 갖지 않고, 전부 동일한
   고정 크기로 렌더링된다. 이 값은 DB에 저장하는 게 아니라 렌더링 상수(현재
   `SeatMap.tsx`의 38px 원형)를 교체하는 방식이며, 폐지되는 `table` 장식 요소들의 평균
   크기(26×16%)를 근거로 구현 시점에 구체 값을 정한다. 저장값이 아니므로 이미 배치된 좌석도
   코드 배포와 동시에 새 크기로 즉시 반영된다("실시간 반영"의 실체 — 별도 마이그레이션 불필요).
6. **좌석 복제(복사) 기능 신설**: 운영자가 좌석 관리 툴에서 기존 좌석을 복사해 빠르게 추가할
   수 있다. 트리거 UI와 라벨 자동 증가 여부는 미확정 — 구현 시점에 정한다.

## 버린 대안

- **좌석에도 개별 `width`/`height` 컬럼 추가해 크기 조절 가능하게** — 검토됐으나, 사용자가
  "동일한 크기로 확정해 버리기"를 명시적으로 선택 — 좌석 크기는 통일하고 배치의 자유도는
  장식 요소(제한 없는 box/door/text/line)로 확보하는 쪽으로 역할을 나눔
- **운영자 설정 화면도 `SeatMap` 컴포넌트를 공유하도록 리팩토링** — 사용자가 "여긴 이미
  관리 에디터/툴이 있으니까" 제외를 명시 — 지금은 두 구현을 통합하지 않고 각자 미니맵/줌/팬을
  자체 구현하는 것으로 확정(리팩토링 여부는 코드 작업 시점에 별도 판단)

## 데이터 영향

- `venue_layout_items.kind` CHECK 제약을 `('table','box','door','text')`에서
  `('box','door','text','line')`으로 변경하는 마이그레이션 필요 (기존 `table` 행 처리 방식은
  미확정 — 그대로 두고 렌더링만 무시할지, `box`로 일괄 변환할지 코드 작업 시 결정)
- `venue_seats`에는 스키마 변경 없음 (크기가 저장값이 아니라 렌더링 상수이므로)

## 후속 작업

실제 결정 내용이다.

### 미확정이었던 항목의 결정

**1. 좌석 고정 크기 = 캔버스 너비의 8% (`SEAT_SIZE_PCT`)**
폐지되는 `table`(26×16%)의 **짧은 변 16%의 절반**을 골랐다. 테이블 하나에 좌석이 여러 개
붙는 실제 배치를 생각하면 좌석은 테이블 깊이보다 확실히 작아야 하고, 절반이면 한 변에 두
자리가 자연스럽게 들어간다. 390px 캔버스에서 약 31px로 기존 하드코딩 값(38px)과도 비슷해
기존 매장의 배치가 크게 흐트러지지 않는다.
**px가 아니라 %로 바꾼 것이 핵심**이다 — 확대가 "콘텐츠를 실제로 키우는" 방식이라, px로 두면
배경 배치 요소만 커지고 좌석은 그대로 남아 확대할수록 배치가 어긋난다. 이건 이번에 확대를
넣으면서 드러난 문제라 ADR 작성 시점엔 보이지 않았다.

**2. `line` 좌표 모델 = 기존 컬럼 재사용 + `rotation` 컬럼 신설**
새 컬럼을 4개(x1,y1,x2,y2) 추가하는 대신 기존 `position_x/y`(중심)+`width`(길이)를 그대로
쓰고, 회전각만 `rotation double precision` 하나로 추가했다. 두께는 저장하지 않고 렌더링
상수(2px)로 고정했다 — 확대해도 굵어지지 않아야 구역 구분선으로 읽힌다.
**회전을 반드시 넣어야 했던 이유**: 축에 나란한 선만 그릴 수 있으면 "얇은 box"와 기능이 겹쳐,
방금 `table`을 폐지한 것과 똑같은 중복 문제를 다시 만들게 된다. 편집 화면에서는 선을 선택했을
때만 위쪽에 동그란 회전 핸들이 뜬다.

**3. 복제 트리거 = 선택 패널의 "복사하기" 버튼, 라벨은 끝자리 숫자 증가**
캔버스 위 우클릭/롱프레스는 이미 드래그·이동 제스처가 쓰고 있어서, 편집 액션은 기존 "삭제"
버튼과 같은 자리(선택 패널)에 모았다. 라벨 규칙은 `nextDuplicateLabel()`(`src/lib/seatLabel.ts`,
단위 테스트 있음) — 원본 라벨 끝의 숫자를 안 쓰인 값이 나올 때까지 올린다("A1"→"A2", 이미
"A2"가 있으면 "A3"). 끝에 숫자가 없으면 " 2"를 붙인다("창가"→"창가 2"). 좌석 추가처럼 그냥
최대번호+1을 주지 않은 이유는, 좌석 라벨이 손님이 실제 자리를 찾는 단서라 원본과의 연관이
보여야 하기 때문이다("A1"을 복제했는데 "7"이 나오면 어느 자리인지 알 수 없다).
복제본은 원본 대비 +4%,+4% 위치에 놓아 원본을 가리지 않게 했다.

**3-1. (2026-08-13 추가) 복사하기 버튼은 배치 요소(네모/출입문/텍스트/선)에도 동일하게 적용**
최초 구현은 `selection.type === 'seat'`일 때만 버튼을 노출해 좌석 전용 기능이었다. 프리뷰
테스트 중 사용자가 "예약석"이라는 이름의 네모(box)를 복사하려다 버튼이 안 보인다고 보고 —
운영자가 구역/테이블을 나타내는 데 `box`를 쓰는 게 자연스러운 이상, 좌석에만 복제를 허용할
이유가 없었다. `handleDuplicateSeat`를 `handleDuplicate`로 일반화해 `selection.type`에 따라
`venue_seats`/`venue_layout_items` 중 맞는 API를 호출하도록 바꾸고, 버튼은 선택 여부와 무관하게
항상 노출한다. 라벨 규칙은 그대로 재사용하되, 라벨이 없는 요소(빈 이름의 네모/선)는 굳이 번호를
붙이지 않고 그대로(`null`) 복사한다 — 화면에 표시되지도 않는 값에 번호를 매기는 건 의미가 없다.
위치 오프셋(+4%,+4%)과 크기/회전은 원본 값을 그대로 넘겨 원본과 동일한 모양으로 복사된다.

**4. 기존 `table` 행 처리 = `box`로 일괄 변환** (마이그레이션 `0017`)
"그대로 두고 렌더링만 무시"는 기각했다 — 운영자가 배치해둔 테이블이 배포 순간 화면에서 소리
없이 사라지고, DB엔 새 CHECK 제약을 위반하는 행이 남아 그 매장의 이후 배치 수정이 전부
실패하게 된다. `box`는 이 ADR이 지정한 대체 종류이고 좌표/크기/라벨이 그대로 보존되므로,
변환하면 운영자 눈에는 배치가 그대로 유지된다.

### 구현 범위 정정 — 방 화면 운영자 뷰도 `SeatMap`으로 통합
이 ADR은 "`SeatMap`에 한 번 구현하면 세 화면에 자동 반영"이라고 적었지만, 실제 코드에서는
**방 화면의 운영자 좌석 이동 뷰가 `SeatMap`을 쓰지 않는 별도의 인라인 캔버스**였다(손님
읽기전용 뷰만 `SeatMap` 사용). 그대로 두면 운영자만 확대/미니맵이 없게 되어 이 ADR의 결정 2를
못 지키므로, 운영자 뷰를 `SeatMap`으로 통합하고 운영자 전용 상호작용(롱프레스 좌석 이동 /
짧게 눌러 케어 메뉴 / 닉네임·착석시간 캡션)만 prop으로 얹었다. 이 통합은 "운영자 **설정**
화면은 `SeatMap`을 공유하지 않는다"는 결정과 충돌하지 않는다 — 그건 `/operator/settings`
편집기 얘기고, 여기는 방 화면이다.

부수 효과로 롱프레스와 화면 이동 제스처가 한 요소에서 겹치게 되어, 캔버스를 끌어 이동한
경우엔 좌석의 pointerup 동작(케어 메뉴/이동 확정)을 건너뛰도록 `wasDragged()` 가드를 뒀다.

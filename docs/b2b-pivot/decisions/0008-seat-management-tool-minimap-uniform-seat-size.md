# ADR-0008: 좌석 관리 툴 — 미니맵/확대축소/드래그 전 화면 적용 + 장식 요소 종류 정리 + 좌석 크기(박스 비례 fit)

- **상태**: Accepted (문서만, 코드 미착수)
- **날짜**: 2026-08-12
- **관련 문서**: `BUSINESS_RULES.md` §2.8, ADR-0007(같은 화면군의 UI 확장을 이어감)

## 맥락

ADR-0007에서 참여자 좌석 선택 화면에 미니맵+뷰포트+선택완료 버튼을 확정했다. 사용자가
이어서: 사장님(운영자)의 매장 규모가 천차만별이고 2층·3층 등 다층 매장도 있어, 운영자 설정의
좌석 배치 편집 화면에도 같은 확대/축소·미니맵이 필요하다고 요청했다. 코드 확인 결과 이
화면(`/operator/settings/[id]/seats`)은 `SeatMap` 컴포넌트를 재사용하지 않는 독자적인
편집기라, 참여자 좌석 선택 화면(`/room/[code]/seat`)·방 화면(`/room/[code]`)과는 구현이
분리되어 있다 — 후자 둘만 `SeatMap` 컴포넌트를 공유한다.

논의 중 추가로 확정된 것: (1) 장식 요소 `table` 종류가 `box`와 기능이 겹쳐 폐지, 대신 `line`
신설, (2) 장식 요소 크기 제한(최소 4%, 최대 제한 포함) 전면 폐지, (3) 좌석 크기는 `box`(네모)
장식 요소들의 평균 크기에 비례해 실시간으로 fit, (4) 좌석 복제 기능 신설.

**(2026-08-12 정정)** 이 문서 최초 초안은 (3)을 "폐지되는 `table` 장식 요소들의 평균 크기를
근거로 산출한 고정 상수"로 잘못 기록했었다. 실제 사용자 의도는 그게 아니라 — **좌석 크기가
`table`이 아니라 `box`(네모)의 평균 크기에 비례해서, 렌더링 시점마다 실시간으로 계산되는
파생값**이라는 것. box 평균이 크면 좌석도 커지고 작으면 좌석도 작아진다("네모 크기에 맞게
fit"). 아래 결정/데이터영향/후속작업 항목은 정정된 내용으로 갱신했다.

## 결정

1. **운영자 설정 좌석 편집 화면**(편의상 "좌석 관리 툴"이라 부르되 이건 정식 명칭이 아니라
   비공식 호칭 — 사용자가 명시적으로 "이름은 편한 대로 부를 것"이라고 확인)에 전체 배치
   미니맵 + 현재 뷰포트 표시 + 확대/축소/드래그(터치 핀치·마우스 스크롤/드래그 전용, 별도
   버튼 없음)를 자체 구현으로 추가한다.
2. **좌석 배치도(캔버스)를 보여주는 다른 모든 화면**에도 동일한 미니맵+뷰포트+확대/축소/드래그를
   똑같이 적용한다 — 참여자 좌석 선택 화면, 방 화면의 자리배치도(손님 읽기전용 뷰 + 운영자
   좌석 이동 뷰), **매장 상세 바텀시트의 좌석 탭(§2.7)**. **(2026-08-12 범위 정정)**: 애초엔
   바텀시트 좌석 탭이 `SeatMap`을 안 쓰는 단순 점유 숫자 카운트(`VenueDetailSheet.tsx`
   구현)라 제외했으나, 사용자가 "좌석배치도인데 왜 빼냐"고 지적 — 원래 §2.7 규칙 문구도
   "어떤 좌석이 비어있는지"였지 집계 숫자가 아니었다. 이 탭도 실제 `SeatMap` 캔버스로
   렌더링하도록 승격하고(비참여자 읽기전용, 클릭 불가), 미니맵 적용 대상에 포함한다.
3. **장식 요소(`venue_layout_items`) 종류 변경**: `table` 폐지(→ `box`로 대체 가능), `line`
   신설. 최종 종류: `box` / `door` / `text` / `line`.
4. **장식 요소 크기 제한 전면 폐지**: 기존 `MIN_SIZE_PCT`(4%) 최소 크기 제한과, 존재했던 최대
   크기 제한을 모두 없앤다 — 매장이 넓거나 다층인 경우 확대해서 아주 작게 배치하고 선/텍스트로
   자유롭게 안내할 수 있어야 하기 때문.
5. **좌석 크기 — box 평균 크기에 비례한 실시간 fit**: 좌석(`venue_seats`)은 개별 크기 조절
   기능을 갖지 않지만(운영자가 좌석 하나하나를 따로 조정할 수는 없음), 크기 자체는 고정
   상수가 아니라 **그 매장의 `box`(네모) 장식 요소들의 평균 크기에 비례한 파생값**이다 — box
   평균이 커지면 좌석도 커지고, 작아지면 좌석도 작아진다. DB에 저장하지 않고 렌더링 시점마다
   그 매장의 box 평균 크기로부터 계산한다(현재 `SeatMap.tsx`의 38px 원형 고정값을 이
   비례 계산으로 교체). 저장값이 아니라 매번 재계산하는 파생값이므로, 운영자가 box 크기를
   바꾸면 이미 배치된 좌석도 별도 마이그레이션 없이 그 즉시 따라 바뀐다. 정확한 비례식(계수,
   box 대비 몇 %인지)과 box가 하나도 없는 매장의 기본값은 미확정 — 구현 시점에 정한다.
6. **좌석 복제(복사) 기능 신설**: 운영자가 좌석 관리 툴에서 기존 좌석을 복사해 빠르게 추가할
   수 있다. 트리거 UI와 라벨 자동 증가 여부는 미확정 — 구현 시점에 정한다.

## 버린 대안

- **좌석에도 개별 `width`/`height` 컬럼 추가해 좌석마다 다른 크기 지정** — 검토됐으나, 사용자가
  "좌석은 (그 매장 안에서) 동일한 크기"를 유지하되 크기 자체는 box 평균에 비례해 정하길 원함 —
  좌석 간 개별 차등은 없고, 매장 단위로 하나의 계산된 크기를 공유하는 쪽으로 확정
- **좌석 크기를 고정 상수로 못박기(`table` 평균 크기 근거)** — 최초 초안에서 이렇게 잘못
  기록했으나, 실제로는 box 평균에 비례한 실시간 파생값이어야 함 — 정정
- **운영자 설정 화면도 `SeatMap` 컴포넌트를 공유하도록 리팩토링** — 사용자가 "여긴 이미
  관리 에디터/툴이 있으니까" 제외를 명시 — 지금은 두 구현을 통합하지 않고 각자 미니맵/줌/팬을
  자체 구현하는 것으로 확정(리팩토링 여부는 코드 작업 시점에 별도 판단)

## 데이터 영향

- `venue_layout_items.kind` CHECK 제약을 `('table','box','door','text')`에서
  `('box','door','text','line')`으로 변경하는 마이그레이션 필요 (기존 `table` 행 처리 방식은
  미확정 — 그대로 두고 렌더링만 무시할지, `box`로 일괄 변환할지 코드 작업 시 결정)
- `venue_seats`에는 스키마 변경 없음 — 크기가 저장값이 아니라, 렌더링 시점에 그 매장
  `venue_layout_items`(kind='box')의 `width`/`height` 평균으로부터 매번 계산하는 파생값이기
  때문 (Atmosphere Index 등 다른 파생값 도메인과 동일 원칙: 원본은 box 크기, 좌석 크기는
  매번 재계산)

## 후속 작업

**코드 미착수.** 구현 시 필요한 것:
- 운영자 설정 좌석 편집 화면: 미니맵/뷰포트/줌·팬 제스처 핸들링 자체 구현
- `SeatMap` 컴포넌트: 동일한 미니맵/뷰포트/줌·팬 추가 (좌석 선택 화면·방 화면·매장 상세
  바텀시트 공용이라 여기 한 번만 구현하면 세 화면에 자동 반영)
- `VenueDetailSheet.tsx`의 좌석 탭을 집계 숫자 카운트에서 `SeatMap` 캔버스(읽기전용) 렌더링으로 교체
- `LayoutItemShape`/에디터의 `kind` 목록에서 `table` 제거, `line` 렌더링(두 점 또는
  위치+각도+길이 등 좌표 모델은 미확정) 추가
- `MIN_SIZE_PCT` 및 존재하는 최대 크기 제한 코드 제거
- 좌석 크기 계산 로직 신설 — 그 매장 `venue_layout_items`(kind='box') 평균 크기를 구해 비례식
  적용, `SeatMap.tsx`의 38px 고정값을 이 계산으로 교체. 비례식/계수, box 0개일 때 기본값 확정
  후 `VARIABLES.md` 갱신
- 좌석 복제 UI/API 신설
- `venue_layout_items.kind` CHECK 제약 마이그레이션 + 기존 `table` 행 처리 방식 결정

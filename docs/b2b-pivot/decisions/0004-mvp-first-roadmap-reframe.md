# ADR-0004: 로드맵을 가설 검증/MVP 중심으로 재구성

- **상태**: Accepted
- **날짜**: 2026-08-10
- **관련 문서**: `ROADMAP_V2.md` "핵심 가설과 MVP 로드맵" 섹션, `MILESTONES.md`

## 맥락

지금까지 `ROADMAP_V2.md`는 Phase 1부터 10까지 순서대로 기능을 전부 만든다는 전제로 짜여
있었다. 그 순서를 그대로 따라 운영자 대시보드, 직원 교대/친절도 투표, 손님 케어(경고
메시지), 좌석 배치 에디터까지 구현했는데, 정작 "손님이 매장에서 이 앱을 실제로 켜서 쓸
것인가"라는 가장 기본적인 가설이 아직 검증되지 않은 상태였다. 사용자가 이 순서 자체가
잘못됐다고 지적 — 지금은 기능을 다 갖추는 단계가 아니라 가설 검증(PMF 탐색) 단계다.

## 결정

`ROADMAP_V2.md`에 "핵심 가설과 MVP 로드맵" 섹션을 문서 맨 앞에 신설하고, 지금부터 우선순위
판단의 기준으로 삼는다:

- **핵심 가설**: 손님이 매장에서 이 앱을 실제로 켜서 쓴다
- **v0.1.0 (다음 목표)**: 지도(Discovery 홈) 없이 QR 스캔 → 방 화면(하트/HOT/별점/채팅)만
  동작하는 최소 루프. 지도는 코드를 지우지 않고 접근만 막는다(ADR과 별개로 `MILESTONES.md`에
  구현 방식 기록)
- **보류**: Staff(교대/친절도 투표), Guest Care(운영자 경고 메시지/좌석 강제 이동) — 손님
  숫자가 적은 검증 단계에선 가치가 작음
- **v0.2.0**: 지도 포함 현재 `main` 전체 범위 — 발견 경로 가설까지 검증하고 싶을 때
- 그 이후(Subscription/Review/대시보드 고도화/Phase 10 필터 등) 순서는 지금 못 박지 않고
  파일럿 피드백을 보고 정한다

기존 Phase 1~10 상세 스코프(`ROADMAP_V2.md` "Phase 히스토리")는 삭제하지 않고 그대로 둔다 —
이미 완료된 기록이고, 보류된 기능들의 설계 자체는 여전히 유효하다. 다만 **착수 순서는 이제
Phase 번호가 아니라 위 MVP 로드맵이 결정**한다.

## 버린 대안

- **기존 Phase 9.5(Subscription) → 10(대시보드 필터) 순서를 그대로 유지** — 이미 만든
  기능(Staff/Guest Care)에 이어 계속 기능을 쌓는 흐름이라, "가설이 아직 검증 안 됐다"는
  문제를 그대로 남긴다. 폐기
- **로드맵을 완전히 새 파일로 다시 씀 (`ROADMAP_V3.md`)** — `CHANGE_INTAKE_PROCESS.md`의
  "로드맵은 항상 최신 버전 하나만 유지한다" 원칙과 어긋나 폐기, 기존 파일 안에서 재구성

## 후속 작업

- 파일럿 매장 찾기 (비개발 트랙, 사용자 담당)
- v0.1.0을 위한 지도 게이팅 구현 착수 여부 확인 (아직 코드 미착수)

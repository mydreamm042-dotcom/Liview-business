# MySTAR B2B Pivot — 문서 안내

B2C 앱을 매장 운영자용 B2B SaaS로 확장하는 작업의 문서 모음. 초기 설계 초안(v1/v2, 요약본, 다이어그램, 구식 태스크 체크리스트 등)은 아래 문서로 전부 흡수되어 삭제했다 — 지금은 이 문서들만 최신이다.

## 문서 구조

### 1. `BUSINESS_RULES.md` — 권위 문서 (Business Rule)
도메인별 규칙의 단일 원천. Part 0(도메인 정의) → Part 1(기존 B2C, 변경 금지) → Part 2(신규 B2B 규칙). 새 기능을 추가하기 전엔 항상 여기에 도메인 매핑부터 한다.

### 2. `ROADMAP_V2.md` — 권위 문서 (Phase 순서)
Phase가 몇 번째인지, 무엇이 끝났고(✅) 무엇이 진행 중인지의 단일 기준. 각 Phase 상세 스코프/확정/미확정 항목도 여기 있다.

### 3. `CHANGE_INTAKE_PROCESS.md` — 프로세스 문서
작업 중 새 아이디어가 생길 때마다 반복하는 절차: 도메인 매핑 → 로드맵 영향 분석 → 승인 → 구현(Business Rule 문서 커밋이 코드보다 항상 먼저).

## 실제 스키마/마이그레이션
설계 초안 SQL이 아니라 `supabase/migrations/*.sql`이 실제 적용된 스키마의 유일한 원천이다.

## 문서 관리 원칙
- 새 기능/규칙 변경은 항상 `BUSINESS_RULES.md`(그리고 필요하면 `ROADMAP_V2.md`)를 먼저 수정·커밋한 뒤 코드에 반영한다.
- 이미 완료된 Phase의 코드는 재작업하지 않는다 — 실제 운영 방식과 설계가 어긋나 사용자가 직접 바로잡은 경우만 예외로, `ROADMAP_V2.md`에 그 사실을 명시하고 진행한다.
